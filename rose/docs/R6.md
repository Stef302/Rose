## 1. Dispatch — vérifié à neuf (sonde `eprintln!`, binaire jetable retiré)

Une sonde insérée dans `jit.rs::carres_acc_natif`, `jit.rs::flottants_acc_natif`
et `interp.rs::sp5_carres_acc`, compilée dans un binaire jetable, donne sur **une
exécution de `bench_global.rose`** (rc=0) :

```
R6 HIT interp::sp5_carres_acc 1 10000001 0
R6 HIT jit::flottants_acc_natif 1 1000001 1 0
```

**Aucun `HIT` côté `carres_acc_natif`.** Cause exacte (lecture de `interp.rs`,
lecture seule) : `appel_rir_direct` (l.3883-3914) récupère la closure native,
puis teste `sp5_carres_plan` et sert `sp5_carres_acc` dès que le plan RIR
correspond — ce qui est le cas de la fonction synthétique `__rose_loop_0` du
banc. Le noyau `jit.rs` n'est atteint que par la **voie d'appel ordinaire**
`appeler()` (l.2271-2298), qui appelle `f(args)` sans test SP5.

Preuve que le noyau `jit.rs` est **réellement appelable** : avec
`ROSE_NO_RIR_PRINCIPAL=1`, le principal est interprété, l'appel à la boucle
passe par `appeler()` et la sonde donne :

```
R6 HIT jit::carres_acc_natif 1 1000001 0
```

Donc : le noyau livré dans `jit.rs` n'est **pas** du code mort en général ; il
est simplement **hors du chemin du banc global**. C'est une propriété du
dispatch de `interp.rs`, hors périmètre (lecture seule).

## 2. Noyau carrés — optimisation livrée, mais sans effet sur le global

`carres_acc_noyau` (nouveau point d'entrée `pub(crate)`, appelé par
`carres_acc_natif`) expose le noyau NEON 16 accumulateurs déjà validé en RC1.
Même calcul exact, aucun changement d'algorithme : `fin ≤ 2²⁴` ⇒ `a² ≤ 2⁴⁸`,
`vmlal_u32` produit élargi sans arrondi, 32 voies u64 vidées en i128 tous les
8192 tours, queue scalaire. Aucune formule fermée, aucune borne du banc, aucun
résultat codé en dur.

### 2.1 Micro-jumeau (`rustc -O`, 10⁷ termes, 13 tirs, médianes, ns)

| Noyau | c16 | c6 | Sortie |
|---|---:|---:|---|
| **NEON 16 accumulateurs (livré)** | **418 559** | **418 463** | `333333383333335000000` |
| NEON 16 (variante `carre_variants`) | 425 631 | 424 863 | idem |
| NEON 32 accumulateurs, 128 termes/tour | 589 935 | 588 655 | idem — **×1,39 plus lent, rejeté** (débordement de registres) |
| SVE2 8 vecteurs Z | 1 138 078 | 1 138 941 | `38185478153982174144` — **faux et ×2,7 plus lent, rejeté** |
| `i64` naïf Rust (`t += i*i`) | **32** | **32** | `1291990006563070912` (débordement) |

Le dernier chiffre est la **décision centrale** : LLVM reconnaît la somme de
carrés `i64` comme un polynôme et la remplace par une **forme fermée** (~32 ns,
soit ~13 000× plus rapide que le calcul terme à terme). Rose doit rendre la
somme **exacte** en i128 et calculer chaque carré (contrainte explicite de la
mission : pas de formule fermée). **Aucun noyau terme à terme ne peut battre
32 ns** ; le dépassement de Rust sur les carrés est donc impossible ici, et ce
n'est pas un défaut d'implémentation.

## 3. Noyau flottant — plancher `fadd` prouvé, aucun code modifié

`flottants_acc_natif` est le seul noyau `jit.rs` réellement utilisé par le
banc global (sonde §1). Micro-jumeau `rustc -O`, 10⁶ itérations, 13 tirs,
`black_box`, c6 **et** c16, médianes (ns) — **tous les variants rendent les
mêmes bits f64** (`4624292002893000918`, `14.392726722864989`) :

| Variante | c16 | c6 | Verdict |
|---|---:|---:|---|
| `x += c/b` scalaire (**noyau livré**) | 514 687 | 514 799 | référence |
| chaîne d'additions seule (`x += 1.0`) | 514 671 | 512 911 | identique |
| divisions NEON 2 voies (`vdivq_f64`) | 514 527 | 515 007 | aucun gain |
| déroulage ×4, ordre IEEE préservé | 513 999 / 512 927 | 514 095 / 512 927 | dans le bruit |
| déroulage ×8, ordre IEEE préservé | 513 775 / 512 911 | 514 111 / 512 927 | dans le bruit |

Écart maximal entre variantes ≈ 0,3 %, inférieur à la dérive A/A. Le coût est
exclusivement la **latence de la chaîne de dépendance `fadd`** : chaque `x`
dépend du précédent ; la division est recouverte par l'exécution hors-ordre
(la chaîne d'additions seule coûte le même temps). Réassocier ou vectoriser
l'accumulation casserait l'ordre IEEE et les 11 valeurs. **LLVM est ici au
plancher et ne peut pas être battu sans changer le résultat** : c'est prouvé,
pas supposé. Aucun changement de code livré, seulement la documentation du
constat (commentaire dans `jit.rs`).

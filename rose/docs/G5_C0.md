## 2. Primitives implémentées (ordre demandé)

Toutes sont émises comme de **vraies routines machine** et câblées dans le
dispatch `app` de `g5_eval`, à la place de `g5_emit_stub0`.

1. **C0.1 `quitter`** — `g5_emit_quit` : `asr x0,x0,#3` (désétiquetage du code
   Rose), `mov x8,#93`, `svc #0`, `ret` inatteignable. Empêche la retombée dans
   l'ancien compilateur source→ELF de `$principal`.
2. **C0.2 `caractere`** — `g5_emit_car` : `asr x10,x0,#3`, `and x10,x10,#255`,
   allocation en ligne de 24 octets, descripteur `[1][1][octet]`, `orr x0,x0,#1`.
   L'octet est gardé dans x10 car `g5_alloc_inline` détruit x0/x1/x2/x9.
3. **C0.3 `partie_entiere`** — `g5_emit_par` : `asr` puis `lsl` (l'argument est
   déjà un quotient entier : le `/` de `(app partie_entiere (bin / ...))` émet
   un `sdiv`). Comme l'ABI G5 n'a pas de rationnels, le cas littéral
   `(app partie_entiere (f a/b))` est replié **à l'émission** dans `g5_eval`
   (les 18 appels de l'émetteur utilisent `(bin / ...)`, donc ce repli ne
   touche pas le point fixe).

Réservation d'étiquettes : `$g5_quitl`, `$g5_carl`, `$g5_parl` sont ajoutés
**après** `$exitl` dans la suite de `g5_next()`. Aucune de ces routines
n'utilise de label interne `$lbl+N` : aucun décalage des nombres magiques
l.2286-2344 n'a été nécessaire.

### Correctifs annexes (toujours dans le seul fichier possédé)

- `chaine(b vraie)` / `chaine(b faux)` : les littéraux booléens n'ont pas de
  slot dans `$g5_sbool` ; sans repli, ils sortaient `1`/`0` au lieu de
  `vrai`/`faux`. Nécessaire pour le passage 19/20 → 20/20 du test critique.
- Boucle de `g5_parse` : `et` est un **AND bit à bit non court-circuitant**
  sous G5 (`g5_eval` émet `andr`). L'ancienne condition
  `tant_que ($i < longueur($ll) et ... $ll[$i] ...)` accédait à `$ll[9]`
  hors bornes → `0` → `longueur(0)` → SIGSEGV. La borne est désormais testée
  seule et l'accès a lieu dans le corps (comportement natif inchangé).
- `g5_elf()` : assemblage de la sortie par paires (`g5_assemble`) en O(n log n)
  au lieu de 134 000 concaténations O(n²) sous le runtime G5 (la concaténation
  native de Rose est structurelle et ne copie pas).
- `p_memsz` du mapping RW : 2 Gio → 8 Gio (mapping anonyme paresseux).
  **Honnêteté** : ce changement a été décidé à la suite d'un crash
  initialement **mal diagnostiqué** — j'avais lancé `host.elf` (qui est la
  compilation de `emetteur.rose`, pas de l'émetteur) sur un fichier RIR :
  c'était l'ancien compilateur qui traitait du texte RIR comme du source,
  sans rapport avec C1. Le changement est inoffensif et vérifié (point fixe
  identique, ELF hôte md5 inchangé), mais il n'était pas nécessaire.

## 6. Tentative C1 — auto-exécution de l'émetteur : ÉCHEC, blocage nommé

Chaîne réelle (le vrai test, après correction de mon erreur de diagnostic §2) :

```
rose rir compilateur/emetteur_elf.rose        -> e_cur2.rir  294 543 o  md5 08b03dc0568d7fd2b0fbf251782ab977
rose compilateur/emetteur_elf.rose e_cur2.rir -> e_self2.elf  392 292 o  md5 75c4647d8f38a34947cea9290080d9e4
                                                  rc=0, 384,50 s, RSS 109 652 Ko
./e_self2.elf tiny.rir                        -> rc=139, 0 octet, 1,06 s
```

Le binaire généré **émet bien un ELF valide quand il s'exécute lui-même en
mode natif** (chaîne ci-dessus, rc=0, en-tête `\x7fELF`), mais il ne sait pas
encore *exécuter* son propre chemin G5 sur un RIR.

Diagnostic gdb sur `e_self2.elf tiny.rir` (après le correctif de boucle) :

```
pc  0x45eefc   ldr x8,[x5,#8]      # entrée de g5_emit_join
x0  0x0                            # la liste est NULLE
x1  0x60004cb1                     # valeur à joindre (chaîne taguée)
x30 0x452564                       # appelant
```

L'appelant `0x452560` correspond à l'op RIR `0038 expr (app joindre (v g5_fn) (v nm))`
de `e_cur2.rir`. Or `g5_eval` replie toute variable non locale à zéro :
`g5_slot_of()` renvoie -1 pour une globale, puis `g5_load(0, 0)` est émis.
Le RIR de l'émetteur déclare **386 globales** (`globaux 0 1 2 … 386`) :
`$g5_fn`, `$g5_code`, `$g5_ops`, `$g5_ctr`, etc. deviennent 0 dès que
l'émetteur tourne sous G5. C'est le **nouveau point de défaillance**, après
les trois primitives.

Avant le correctif de boucle, le même binaire s'arrêtait plus tôt :
`pc 0x45ec1c` (`g5_emit_len`, `ldr x2,[x1]`, x0=x1=0), causé par l'accès
hors bornes `$ll[9]` décrit au §2. Ce point est corrigé ; le blocage actuel
est bien les globales.

**Verdict honnête : l'objectif C0 complet (auto-exécution de l'émetteur) n'est
pas atteint.** Les trois primitives demandées sont implémentées et prouvées,
mais il faut en plus un mécanisme de **variables globales G5** (adresses RW
fixes + chargement/stockage), hors périmètre de cette mission. Aucun succès
n'a été simulé.

## 2. Schéma de stockage retenu (mesuré)

Cartographie RW retenue, vérifiée par désassemblage des ELF émis et par la
carte mémoire du source :

| Plage | Rôle |
|---|---|
| `0x60000000` | pointeur libre du tas |
| `0x60000010` / `0x60000018` | argc / adresse de argv[0] |
| `0x60000020` (480 o) | tampon de chemin |
| `0x60000200` (144 o) | `struct stat` |
| `0x60000300` (0x2000) | table d'internement des chaînes (512 × 16) |
| `0x60002400` | arguments d'index >= 30 (SH2/SH3) |
| `0x60003000` (0x800) | table des caractères (256 × 8) |
| `0x60003800`..`0x60004000` | scratch décimal, écriture **décroissante** |
| **`0x60004000`..`0x60005000`** | **GLOBALES G5 : 512 × 8 octets** |
| `0x60008000` | début du tas (déplacé depuis `0x60004000`) |

Choix : index global = **index de slot du `$principal`**, adresse
`0x60004000 + 8*index`, valeur Rose **taguée** (ABI x0). La table d'index est
une liste Rose (`$g5_gnams`) construite par `g5_set_globaux()` à la fin du
parsing du `$principal`, en filtrant `noms` par la liste `globaux`. Format des
entrées : `"ix:nom"` regroupés par `|`.

Garde : `g5_gaddr()` refuse tout index hors `0..511` par `g5_fail` ; aucune
écriture hors zone n'est émise. Le mapping RW reste anonyme (`p_filesz=0`,
`p_memsz=8 Gio`) : la zone vaut 0 au départ, donc tag 0 (entier Rose 0).

### Câblage

- `g5_read_var` / `g5_write_var` : priorité au slot local ; dans `$principal`,
  le slot **est** la globale (adresse RW, pas le cadre) ; sinon recherche par
  nom dans `$g5_gnams` ; repli historique à 0 si le nom est inconnu.
- `g5_read_slot` / `g5_write_slot` : `slot N` et `affect slot N` du principal
  vont en RW ; ailleurs dans le cadre.
- Appel `joindre(liste, v)` : écriture de retour par `g5_write_var`, sinon
  une globale qui change de descripteur n'était pas mise à jour.
- Les fonctions sont compilées **après** `g5_parse()` : la table est prête.

### Piège sémantique mesuré

Affecter une globale depuis une fonction crée une **locale** : programme
`$x="" ; fn f(){$x="abc"} ; f() ; >> $x` rend une ligne vide en natif. La
table des globales est donc une liste **mutée en place par `joindre()`**, pas
une variable réaffectée. C'est le premier correctif qui a fait passer
l'incrément `(v x)` de `1` à `8` (g2).

## 3. Blocages suivants, nommés par la mesure

La première self-émission (`e_self3.elf`, 430 860 o) rend rc=2, 0 octet.
`$g5_err` a été lu en gdb à l'adresse de la globale 15 (`0x60004078`) :
4 entrées, dont `op non couverte : 0000 afficher_abstrait entier 3` et
`immédiat hors int64 : -100` (×2). Causes corrigées :

1. **`g5_nu_op`** testait des chiffres avec `caractere >= "0" et <= "9"`.
   Sous G5, `<`/`>=` sur chaînes comparent des **pointeurs tagués** (`cmpr`),
   pas des caractères : le préfixe `"0000 "` n'était pas retiré. Le format
   RIR étant fixe (`main.rs` : `{:04} `), on coupe désormais 5 octets.
2. **`g5_load`** utilisait les bornes `-2^63` et `2^64`, non représentables
   dans l'ABI 61 bits : elles devenaient 0, donc `-100 < 0` déclenchait
   `immédiat hors int64`. Les 16 bits du complément à 2 sont maintenant
   calculés **chunk par chunk** (valeurs <= 65536), sans constante > 2^60.
3. **`g5_make_str`** faisait `% 2^64` pour son hash : 2^64 → 0 sous G5,
   hash constant, réutilisation du mauvais littéral interné. Passé en
   modulo 2^32 (la clé est vérifiée avant réutilisation).
4. **`g4_entier_ou_zero`** validait les chiffres par `"0" <= c <= "9"` :
   même problème de pointeurs. D'où `mov x0,#0` au lieu de `#3` et des
   branches `b` au lieu de `bl` (kind 0 au lieu de 1) dans `e_self4.elf`
   (rc=0, 4 328 o, mais **385 octets différents** et ELF généré rc=139).
   Comparaison sur `ordre($c)` (48..57), identique en natif et sous G5.

Aucune de ces corrections ne touche aux deux sections sources de
`emetteur.rose` : le point fixe est resté identique à chaque jalon.
